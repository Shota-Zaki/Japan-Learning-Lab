# Japan Learning Lab デザイン方針

## FE演習の完成要件

この文書は、FE演習画面の表示・操作・レスポンシブ設計の正本とする。

## 1. 情報設計

- FE Learning Labは科目Aと科目Bを同一サイト内で切り替える。
- 科目Aと科目Bは同一セッションへ混在させず、演習・模擬試験の開始前にどちらか一方を選択する。
- 科目選択は絞り込み条件から独立した単一選択として扱う。
- 選択した科目の中で「分野」「単元」「開催回」「回答状態」を独立した条件群として扱う。
- 同一条件群の複数選択はOR、異なる条件群の組合せはANDで評価する。
- 各条件群へ「全選択」「全解除」を配置する。
- 0件の場合は開始操作を無効化し、該当件数と条件の見直し方法を表示する。
- 選択中の条件はフィルター群より上にチップで要約し、個別解除と全解除を提供する。
- 問題の出典識別情報は内部データに保持するが、問題冊子・解答資料への外部リンクは表示しない。

## 2. 絞り込み表示

- **受験科目**は既存の独立ブロックを維持し、Gridの対象へ含めない。
- Gridの対象は「1. 分野」「2. 回答・復習状態」「3. 開催回・公開区分」「4. 単元」の4ブロックだけとする。
- 採用済みのパターンBを通常表示の既定とし、指定なし・無効値は`filterLayout=2`へフォールバックする。
- `filterLayout=1|2|3`は比較・回帰確認用として維持し、利用者向け切替UIは追加しない。
- パターンBは分野と回答・復習状態を左側へ縦積みし、開催回・公開区分を右側で2段相当使用する。
- その下に単元を全幅カードとして配置する。
- カード高さは内容量で決定し、固定高、強制的な同一高、内部縦スクロールを使用しない。
- Grid間隔とカード内余白は、44px級の操作対象と情報の区切りを維持できる範囲で縮小する。
- 収録データに存在する全単元IDへ完全な日本語表示名を定義する。
- 未登録単元IDを英語のまま画面へ出さず、「単元名未登録」と表示してテストで検出する。
- 単元カードだけは選択肢の最小列幅を広くし、1行表示できる項目を増やす。
- 長い単元名は全文を維持し、`wbr`相当の意味上自然な候補位置だけで改行する。
- 文字単位の強制改行、末尾省略、横スクロールは使用しない。
- 375pxでは「分野 → 回答・復習状態 → 開催回・公開区分 → 単元」のDOM順で1列、768pxでは8列基準、1,280px以上では12列基準とする。
- ページ全体の横スクロール、カードの重なり、内容切れを禁止する。

## 3. 科目B

- 科目Bは「アルゴリズムとプログラミング」と「情報セキュリティ」を区別できる。
- 問題群・共通資料・設問の関係を保持し、共通資料がある場合は設問本文より前に表示する。
- 擬似言語、表、図、注記を通常本文と混在させない。
- 出典識別情報は保持するが、問題冊子・解答資料への外部リンクは表示しない。

## 4. 構造化コンテンツ

問題本文と解説は、次のブロックを順序付きで表示する。

- `paragraph`: 通常の説明文。段落間に余白を設け、改行を保持する。
- `code`: 擬似言語・プログラム・コマンド。等幅書体、横スクロール、行単位の改行を使う。
- `table`: 見出しとセルを持つ表。狭い画面では表全体を横スクロールさせる。
- `list`: 条件、手順、注記などの列挙。
- `note`: 問題固有の前提や注意事項。
- `image`: 公式資料由来の図。代替テキストと出典識別情報を必須とする。

文字列しかない既存問題は、安全な解析処理で段落・コード・表候補へ変換する。解析できない内容は本文として保持し、欠落させない。

## 5. 演習画面

- 本文領域の1行幅を過度に広げない。
- 本文、コード、表、選択肢、解説を視覚的に分離する。
- 問題本文は解説本文より一段強い文字サイズ・ウェイトとし、問題見出し、問題本文、解説見出し、解説本文の差を明確にする。
- 解説本文は問題本文より小さく軽いウェイトとし、詳細解説の各見出しで構造を補強する。
- 通常演習は回答確定後に選択内容を変更できない。
- 模擬試験は終了まで正誤・解説を表示しない。
- 問題移動、未回答移動、見直し、一時停止、終了を維持する。

### 問題一覧

- 進捗表示、問題番号入力、総問題数、移動ボタンを同じ領域に配置する。
- 入力は`1`から総問題数までの整数に限定する。
- Enterと移動ボタンの両方で指定問題へ移動する。
- 無効値では現在問題を変更せず、許容範囲を文字で通知する。
- 問題番号ボタンは現在問題、回答済み、見直し状態を維持する。
- 一覧が高さ上限を超える場合だけ、一覧領域内に縦スクロールを表示する。
- 画面幅に応じた列数を維持し、横方向へ逃がさない。
- 移動後は現在問題のボタンを一覧内の見える位置へ合わせる。

### 詳細解説

- 回答確定後は、正答、正答の根拠、選択肢ごとの判断、関連知識の順で表示する。
- 選択肢本文と判断理由を同じカード内で確認できるようにする。
- 問題全体または選択肢に個別解説が保存されている場合は、そのデータを優先する。
- 個別解説がない場合は未登録であることを明示し、保存データにない技術的理由を生成しない。
- 関連知識は保存済み単元、キーワード、タグから重複を除いて表示する。
- 通常演習と完了後レビューは同一の詳細解説表示を使用する。

## 6. 模擬試験と結果レビュー

- ランダム模擬試験は、選択した科目から本番と同じ問題数をランダムに出題する。
- 2022年12月公開サンプル問題は、ランダム模擬試験とは別の固定セットとして提供する。
- 固定サンプルは科目A 60問・90分、科目B 20問・100分とする。
- 固定サンプルは公式問番号順を維持し、問題の抽出・並べ替え・ランダム化を行わない。
- 固定セットに欠落がある場合は暫定問題数で開始せず、開始操作を無効化する。
- 科目Aの図表付き問題を含め、問題本文・選択肢・図表・正答が揃った状態だけを公開する。
- 模擬試験終了前は正誤と解説を表示しない。
- 模擬試験中の残り時間はサイトヘッダー右上の空き領域へ固定し、スクロール中も常時表示する。
- 375px、768px、1,280px以上で固定タイマーがブランド、ナビゲーション、問題本文、主要操作を覆わないことを確認する。
- 完了後は各問題をキーボード操作可能な開閉ブロックとして表示する。
- 完了後の詳細には問題文、選択肢、ユーザー回答、正答、正誤または未回答、詳細解説を表示する。
- 単一正答、複数正答、未回答を同じ表示規則で扱う。

## 7. 問題データ分類

公式公開データは次の区分を保持する。

- 通常公開問題
- 科目A免除制度の修了試験問題
- 新形式移行時のサンプル問題
- 旧形式の公開過去問題

重複判定は、科目、問題文、選択肢、正答を正規化した指紋で行う。同一問題を複数資料から確認できる場合は、代表出典と追加出典を分離して保持する。

## 8. レスポンシブ

- 375px: 全3パターンを1カラムへ戻し、DOM順とキーボード順を一致させる。問題番号入力と移動ボタンは縦方向へ再配置し、表とコードのみ横スクロールを許可する。
- 768px: 主領域1カラムを基本とし、絞り込みは8列基準の非対称配置を使う。問題一覧は内部縦スクロールを維持する。
- 1280px以上: 絞り込みは12列基準のモジュール不規則型、問題本文と問題ナビゲーションは2カラムにする。
- ページ全体の横スクロールは禁止する。
- タップ対象は原則44px以上を確保する。

## 9. アクセシビリティ

- 全操作をキーボードで実行できる。
- 開閉状態、選択状態、選択数を支援技術へ伝える。
- 3パターンの視覚配置はDOM順とラベル関連付けを変更しない。
- 問題番号入力へラベル、最小値、最大値、エラー関連付けを設定する。
- 現在問題は`aria-current`で伝える。
- スクロール可能な問題一覧はキーボードフォーカスを受け取れるようにする。
- 色だけに依存せず、文字・アイコン・枠線で状態を表す。
- 結果レビューはネイティブの開閉要素を使用し、フォーカス位置を視認できるようにする。
- 詳細解説は画面階層に応じて見出しレベルを維持する。

## 10. GitHub Pages

- GitHub Pages用成果物はRepository直下の`docs/`へ生成する。
- プロジェクトサイトのベースパスを考慮し、直接URLと再読込でアセットを失わない。
- `docs/index.html`と`docs/404.html`を同じアプリ入口として生成する。
- `docs/.nojekyll`を含める。
