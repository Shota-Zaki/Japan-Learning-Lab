# Java Learning Lab 初期監査・実装境界

## 対象

- 移行元: `Shota-Zaki/Engineer-License-Lab` の `main`
- データ正本候補: `docs/java/data/questions.js`
- 移行先: `Shota-Zaki/Japan-Learning-Lab` の `work`
- 初期実装日: 2026-08-06

## 結論

Java Learning Labは、FE Learning LabのセッションUIと保存ライフサイクルを再利用できる。ただし、問題モデルはFEの単一選択前提を流用せず、Java側で単一・複数正答を同一モデルとして扱う。

初期フェーズはJava Bronzeを実装対象とする。Java Silver SE 17は旧Repositoryに共通Questionリポジトリと単元別互換監査が存在するため利用候補だが、全問題件数・選択肢順・正答ID・解説フィールドの移行監査が完了するまでUIへ公開しない。

## 実装した境界

- Java専用セッションスキーマ `lab: "java"`
- FEと分離した端末保存キー
- Java専用クラウドAPI `/api/java/sessions`
- 単一正答と複数正答を同じ`correctChoiceIds`で判定
- 回答確定後は上書き不可
- 下書き、前後移動用index、見直し、一時停止、再開、完了、履歴復旧に必要な状態を保持
- 間違い、未回答、見直しを次回の問題集合へ変換
- 保存読込時に正答判定を問題データから再計算

## 互換性ルール

1. FEの保存キー、API、D1テーブルは変更しない。
2. Java問題ID、選択肢ID、正答IDは移行元から変更しない。
3. 表示順が意味を持つ選択肢は並び順を保持する。
4. 複数正答は集合一致で判定し、部分一致を正解にしない。
5. 旧模試の時間制限値はデータ監査用に参照しても画面・セッションへ持ち込まない。
6. Silverは互換監査を通過した単元だけ段階的に有効化する。
